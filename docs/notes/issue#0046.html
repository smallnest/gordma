Design Decisions

Decision Rewrote doc.go as the package's narrative overview

Ambiguity: "doc.go 说明：消息语义与流式适配的关系、两种建连方式、两种 poll 模式、批量与零拷贝接口的适用场景、平台支持".

Choice: Expanded the package doc into godoc sections — message semantics vs. stream adapter (incl. the don't-mix caveat), establishment (rdma_cm + handshake), datagrams/addressing/registry, performance knobs (batch, zero-copy, poll modes), and platform support.

Rationale: doc.go is the first thing on pkg.go.dev; it should orient a reader across every feature the series built, with pointers rather than restating each symbol's doc.

Decision CI builds examples explicitly in every job

Ambiguity: "CI 覆盖 rdmanet 包与 examples".

Choice: Added explicit go build ./examples/... steps to the cgo, stub (CGO_ENABLED=0), and cross-compile jobs (the latter now builds both ./... and ./examples/...).

Rationale: Although ./... already includes examples, calling them out as named steps makes an example breakage obvious in the CI log and documents the intent.

Deviations

Deviation None

Implementation followed the spec. All exported rdmanet symbols already carried godoc comments from their introducing issues; this issue verified that and added the package-level narrative + CI coverage.

Tradeoffs

Tradeoff Redundant explicit example build steps vs. relying on ./...

Alternatives: trust go build ./... to cover examples, or add dedicated ./examples/... steps.

Pros/cons: relying on ./... is less YAML; explicit steps are mildly redundant but give a labeled failure and satisfy the criterion's "覆盖…examples" literally.

Chosen: explicit steps — the small duplication buys clearer CI signal and an unambiguous record that examples are gated.
