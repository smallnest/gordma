Implementation Notes

Issue #45 — rdmanet: examples 目录分特性示例 — 2026-06-13

Design Decisions

Decision One independent main package per feature

Ambiguity: "每个特性一个子目录，各含独立 main.go".

Choice: Eight self-contained package main dirs (echo-msg, echo-stream, handshake-dial, packet, batch, zerocopy, registry, pollmode), each with a README. No shared helper package, so each example reads top-to-bottom.

Rationale: Examples are teaching artifacts; cross-file indirection would hurt readability. Independence also means go build ./examples/... validates each in isolation.

Decision Uniform server/client CLI shape with a Supported() guard

Ambiguity: "server/client 通过 flag 区分" + "运行时打印 ErrNotSupported 友好提示".

Choice: Each example takes -l ADDR for server or a positional HOST:PORT for client, and first checks gordma.Supported(), printing a friendly line and returning cleanly when false.

Rationale: Consistent UX across examples; the guard makes them runnable (no crash) on stub platforms, satisfying the criterion.

Deviations

Deviation packet/registry use connectionless addressing, not -l/HOST:PORT

Spec: "server/client 通过 flag 区分".

Implemented: The UD examples (packet, registry) are connectionless, so the client targets the server by its UD Addr string (printed, or looked up via the registry) rather than a listen host:port.

Why: UD has no connection/listen address; forcing a host:port shape would misrepresent the API. They still cleanly split server/client roles via flags.

Tradeoffs

Tradeoff zerocopy example sends the full buffer length

Alternatives: add a length-prefix/trim API to send only the payload, or send the whole registered buffer.

Pros/cons: trimming is friendlier but SendBuffer's v1 contract sends the buffer's full Bytes() length; adding trim would expand the API mid-example.

Chosen: send the full 64-byte buffer (payload + zero padding) and document it. Keeps the example honest about the current SendBuffer semantics.

Open Questions

Question Examples not executed end-to-end

Assumption: They compile on all platforms (verified: go build ./examples/..., CGO_ENABLED=0, windows cross) and the API usage is correct.

Verify: Running them needs two RDMA nodes; the bench tools (#44) exercise the same API paths under load.

Question SendBuffer payload-length ergonomics

Assumption: Sending the whole buffer is acceptable for the example.

Verify: If users commonly send a partial buffer, consider a SendBufferN(b, n) or a settable length on Buffer in a follow-up.
